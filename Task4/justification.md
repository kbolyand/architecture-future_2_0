## Ресурсы и параметры

| Ресурс                | Параметры                                                                                    | Причина                                                                                         |
|-----------------------|----------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------------------|
| Compute `bastion`     | 2 vCPU, 2 ГБ RAM, 20 ГБ network-ssd                                                          | управление и отладка; один охраняемый публичный вход; без business payload                      |
| Compute `portal`      | 2 vCPU, 4 ГБ RAM, 30 ГБ network-ssd                                                          | учебный backend / UI PoC, достаточно для smoke, не нагрузочный production                       |
| Compute `analytics`   | 4 vCPU, 8 ГБ RAM, 30 ГБ boot SSD + 100 ГБ отдельный SSD                                      | демонстрация вычислительного и data диска; **недостаточно для сотен ТБ**, масштабирование позже |
| VPC                   | 1 network, 3 subnets                                                                         | сегментация per tier, CIDR без пересечений, расширение отдельными подсетями                     |
| Shared Egress Gateway | один gateway + default route private subnets                                                 | доступ к обновлениям/репозиториям из private VM без прямого public IP                           |
| Security Groups       | bastion SSH from admin / portal SSH+8080 from edge / analytics SSH from edge + 8123 from app | deny by default на входе, минимальные доверенные маршруты                                       |

Отдельный data SSD создан как ресурс Terraform и привязан к аналитической VM; файловая система **не создаётся**, диск не
зашифрован дополнительно. В продакшене — KMS-backed disk encryption, backups, доступ по ролям, мониторинг, контроль 
расхода диска. Текущие параметры — минимально работоспособный **тестовый** IaaS, а не производственный sizing по объёму 
компании.

На публичном IP только bastion, и SSH ограничен `admin_cidr`. App/data private, исходящий трафик идёт через управляемый 
gateway. 

## Почему выбран Terraform и подход IaC
Terraform позволяет описать всю инфраструктуру Yandex Cloud в виде конфигурационных файлов: виртуальные машины, сети, 
диски и правила доступа. Декларативный подход удобен тем, что мы описываем, какой должна быть инфраструктура, а 
Terraform сам определяет, какие ресурсы нужно создать или изменить. Это упрощает управление и снижает риск ошибок при 
ручной настройке.

Infrastructure as Code (IaC) даёт два основных преимущества:
1) Воспроизводимость. Можно быстро развернуть одинаковую инфраструктуру для разработки, тестирования и продакшена.
2) Масштабируемость. При росте нагрузки достаточно изменить параметры конфигурации или добавить новые ресурсы.

Кроме того, конфигурацию можно хранить в Git, отслеживать изменения и при необходимости возвращаться к предыдущим 
версиям.
